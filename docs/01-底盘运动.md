## 麦克纳姆轮底盘运动

> 完成时间点：2026-10-13　｜　状态：**已定**（轮距 / 轴距 / 辊缝 / 电流为待实测项，见文末清单）

### 1. 目标与验收标准

实现四向平移 + 原地旋转的全向底盘，能通过 0.5 坡比坡道与桥面。

| 手册指标     | 要求               | 本队验收方式                  |
| -------- | ---------------- | ----------------------- |
| 电机运动（全部） | 不少于 4 个电机转动      | 四轮离地逐轮单独给速，前后都能正反转，全过程录制 |
| 底盘运动（全部） | PS2 手柄控制全部车体水平运动 | 车体与 PS2 手柄同时出镜，单手完成四向平移 + 原地旋转 + 复合动作 |
| 进阶项      | 机器人能够上坡          | 录制 0.5 坡比坡道实测           |

| 项                 | 目标值         | 实测值    | 结论     |

### 2. 初版构思

用官方物资表内的 **4×TT 马达（1:48 单轴）+ 60 mm 黄色麦克纳姆轮** 搭标准 4 麦轮底盘。底盘首版（V1/V1.1）用**已采购的四轮金属折弯板**（255×150，自带马达孔），**V2 起改为自打印一体底盘**（原因见 00 号文档「问题 1：金属底盘买回来才发现过不了桥」）。麦轮的好处是能横向平移对位，省掉取物时的反复倒车。

风险预判：

- 手册培训里专门有一课时"麦轮运动学解算"，说明这部分是考察点，不能只抄轮子装上去。
- 麦轮辊子是斜置的，纵向附着约为普通轮的 0.7 倍，坡道上打滑是最大风险。
- **麦轮装配方向极易搞反**：四个轮的辊子朝向必须成对角一致（左前与右后同向、右前与左后同向），从车顶俯视时四组辊子连成 X 形。装成镜像会让侧向分力互相抵消，现象就是"走直线跑偏、横移无力"。

### 5. 遇到的问题与解决

#### 问题 1：麦轮底盘走直线会跑偏

- **现象**：松开手柄后车体并不沿直线滑行，而是向右前方漂移；2 m 行程偏移 `<待实测：跑 2 m 直线量最大横向偏移>` mm，横移时速度明显低于理论值。
- **定位过程**：先单独驱动 4 个轮看转速是否一致（排除马达差异）→ 再交换左右轮（排除装配差异）→ 最后发现 4 个麦轮的辊子朝向装成了**镜像**，没有做到对角一致。
- **根因**：辊子镜像后四个轮的侧向分力两两抵消，纵向推进力不再相等，等效于左右两侧的「有效轮径」不同，车体被推着画弧。
- **对策**：按 X 形重装四个轮（左前与右后同向、右前与左后同向）；顺带把 `Mot_Mecanum()` 的符号约定写进函数头注释，避免后人改一个符号就让横移与自转同时反向。
- **验证结果**：重装后恢复走直线；2 m 行程偏移 `<待实测：重装后复测 2 m 直线最大横向偏移>` mm。

#### 问题 2：0.5 坡比带载爬坡打滑
- **现象**：空载能上，加配重到 2.0 kg 满载后在坡中段打滑——四个轮都在转，车体却往下滑，得退下来重新冲。
- **定位过程**：先空载爬坡（成功）→ 再加 1 kg 配重（成功）→ 加到满载 2.0 kg 后在坡中段打滑；把车放到坡上用手推，测得所需推力明显大于车轮能提供的附着力；再按正压力与附着系数估算，麦轮纵向附着约为普通轮的 0.7 倍，余量不足。⚠️ 注意：手册禁止携带任何粉末或液体用于增摩，**不能靠撒松香 / 胶带解决**。
- **根因**：麦轮辊子斜置，纵向附着力 ≈ 普通轮的 0.7 倍；2.0 kg 沿 26.6° 坡的重力分量约 **8.8 N**，四个 TT 轮能提供的附着力只比它略高，坡中一旦失速就再也起不来。
- **对策**：降低重心（电控盒与电池压到后轴上方）→ 上坡前先加速，不在坡中停顿 → 尽量正对上坡（斜着上会同时消耗侧向分力）→ 仍不够时改走 e1、d8 的 150 mm 台阶坡道。
- **验证结果**：`<待实测（2.0 kg 满载、0.5 坡比、正对上坡）>`。

## 麦轮运动学解算

> 完成时间点：2026-10-14　｜　状态：**已定**（公式已定；Lx / Ly / R 与实车方向为待标定项，见文末清单）

### 1. 目标与验收标准

把 PS2 手柄的（前后、左右、旋转）三路输入，解算成 4 个麦轮的独立目标转速，并保证**平移与旋转可以叠加**。

- 手册对应：统一培训电控组第 4 课时「麦轮运动学解算」——属于培训覆盖内容，文档里写清楚解算过程能体现掌握程度。
- 验收标准：给定 (vx, vy, ω) 能算出 (ω1…ω4)，且实车动作方向与理论一致。

### 2. 初版构思

采用标准麦轮逆运动学。以车体中心为原点，x 向前、y 向左、ω 逆时针为正：

```
ω1（左前）= ( vx - vy - (Lx+Ly)·ω ) / R
ω2（右前）= ( vx + vy - (Lx+Ly)·ω ) / R
ω3（左后）= ( vx + vy + (Lx+Ly)·ω ) / R
ω4（右后）= ( vx - vy + (Lx+Ly)·ω ) / R
```

其中 `vx`、`vy` 为手柄摇杆映射的平移速度，`ω` 为旋转角速度，`Lx`、`Ly` 为半轴距/半轮距，`R` 为轮半径。

> ⚠ **符号约定（必须与代码一致，否则公式与实现会互相矛盾）**：上文公式取 **y 向左为正、ω 逆时针为正**；而 `Mot_Mecanum(fore, side, spin, out)` 取 **`side` 向右为正、`spin` 顺时针（右转）为正**。两套约定差两个负号：`side = −vy`、`spin = −ω`（乘 `(Lx+Ly)/R` 后并入系数）。代入后 `out[0] = vx + side + spin` 恰好等于 `ω1 = (vx − vy − (Lx+Ly)·ω)/R × R`，**代码与公式一致**。写实现时务必把这一段约定写在函数头注释里，否则后人改一个符号就会让横移与自转同时反向。

风险预判：4 个轮子转速要归一化到 PWM 满量程以内，否则复合动作（边走边转）会出现轮子饱和、车体走样。

### 3. 技术选型对比

| 候选方案                            | 优点               | 缺点                    | 结论       |
| ------------------------------- | ---------------- | --------------------- | -------- |
| 查表法：预先测好 8 个方向 + 旋转的 PWM 组合，存成表 | 不需要数学、调试直观       | 无法连续调速；组合动作（边走边转）无表可查 | ❌        |
| **逆运动学公式实时解算**                  | 连续、可叠加、参数改动只需改公式 | 需要标定 Lx / Ly / R      | ✅ **选定** |
| 只做四向平移、不做旋转（省掉 ω 项） | 公式最短，参数只有 Lx / Ly | 操作手无法边接近道具边调朝向，而手册把 ω 项列为考察点 | ❌ |

**为什么这么选**：场地是 2400×2400 mm 的方格，操作手需要在"斜向平移接近道具"的同时微调朝向，组合动作是常态；查表法覆盖不了这种连续叠加，逆运动学只多几行浮点运算。

### 4. 实现过程

- **代码**：`firmware/mecanum.c`（`Mot_Mecanum()`）——**`firmware/` 目前只有 `.gitkeep`，代码尚未入库**，完整实现见下。

四个轮子的转速方向定义（这一段同时写进 `Mot_Mecanum()` 的函数头注释）：

```text
 *   输入 fore / side / spin  —— 前后、左右平移、自转，范围 -100 ~ +100
 *   输出 out[4]             —— 四个轮子转速，-100 ~ +100，正 = 正转
 *   下标：out[0]=左前  out[1]=左后  out[2]=右前  out[3]=右后
 *
 *     前进 = 四个轮子全往前                 ┌ 左前 ↑   右前 ↑ ┐
 *                                          └ 左后 ↑   右后 ↑ ┘
 *     右移 = 左前与右后往前、右前与左后往后   ┌ 左前 ↑   右前 ↓ ┐
 *                                          └ 左后 ↓   右后 ↑ ┘
 *     顺转 = 左侧往后、右侧往前              ┌ 左前 ↓   右前 ↑ ┐
 *                                          └ 左后 ↓   右后 ↑ ┘
```

```c
    /* --- 第 1 步：算四个轮子"应该转多快" ---

    v[MOTOR_FL] = (int32_t)fore + side + spin;   /* 左前轮 */
    v[MOTOR_BL] = (int32_t)fore - side + spin;   /* 左后轮 */
    v[MOTOR_FR] = (int32_t)fore - side - spin;   /* 右前轮 */
    v[MOTOR_BR] = (int32_t)fore + side - spin;   /* 右后轮 */

    /* --- 第 2 步：归一化 ---

    for (i = 0; i < MOTOR_COUNT; i++)
    {
        int32_t a = (v[i] < 0) ? -v[i] : v[i];   /* 取绝对值 */
        if (a > maxabs) maxabs = a;
    }
    if (maxabs > 100)                            /* 没超 100 就跳过，平时按单方向键不进这里 */
    {
        for (i = 0; i < MOTOR_COUNT; i++)
        {
            v[i] = (v[i] * 100) / maxabs;        /* 先乘 100 再除，防止整数除法把小速度抹成 0 */
        }
    }


    /* 输出 */
    for (i = 0; i < MOTOR_COUNT; i++)
    {
        out[i] = (int16_t)v[i];
    }
}
```

**归一化策略**：先算出 4 个轮的转速，取绝对值最大者；若超过 100（PWM 满量程），则四个轮**按同一比例**缩放到 100，方向比例保持不变。实现上先乘 100 再整除 `maxabs`，避免整数除法把低速抹成 0。

### 5. 遇到的问题与解决

#### 问题 1：旋转时车体中心发生平移

- **现象**：只给旋转量时，车体绕着一个不在车体中心的点转，同时整体平移几十毫米；平移与旋转叠加时偏移更明显。
- **定位过程**：先用 ω 单独测试（正常）→ 再用 vx 单独测试（正常）→ 两者叠加后出现偏移 → 回查公式，发现 `Lx` / `Ly` 代入的是整车轴距与轮距，而公式要求的是**半**轴距与**半**轮距。
- **根因**：`Lx` / `Ly` 取了 2 倍值，使 ω 项权重偏大一倍，四个轮的转速差被放大，合力中多出一份平移分量。
- **对策**：改为半值（`Lx = 轴距 / 2`、`Ly = 轮距 / 2`），并把 `Lx` / `Ly` / `R` 提成可标定宏，不再散落在公式里。
- **验证结果**：`<待实测（叠加动作时车体中心的偏移量，2 m 行程）>`。
