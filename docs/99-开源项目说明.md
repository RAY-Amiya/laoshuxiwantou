## 一、填写要求

凡是**不是我们原创**的东西，都要在下表登记，包括但不限于：

- 引用的代码库、驱动、算法实现；
- 参考的开源硬件设计（PCB、原理图）；
- 引用的 CAD 模型、3D 打印件；
- 参考过的开源机器人项目、教程仓库；
- 使用的工具链（编译器、RTOS、上位机脚本库）。

**每一行都要写清**：项目名 → 来源链接 → 版本/commit → 许可证 → **用在哪** → **改了什么**。

> 「版本 / commit」这一格的写法有两种，**按是否引用了对方的文件来选**：
> - **引用过对方的具体文件** → 必须固定到分支 + commit 短哈希（如项目 1 的 `f776832`），否则"用在哪 / 改了什么"无从对应；
> - **只看过 README、未取到也未引用任何文件** → 如实写「**仅登记仓库，未固定版本**」（如项目 2），不臆造哈希，也不留空占位符。**留一个假的或猜的哈希，比坦白写"未固定版本"严重得多。**

### 两个仓库里实际有什么（供填「用在哪」时对照）

**项目 1 `visual_robotic_arm-master`** —— 仓库根目录 **5 项**（语言构成：C 98.3% / Other 1.7%）：

| 仓库内路径 | 内容 | 对我们有用吗 |
|---|---|---|
| `控制部分/robotic_arm_demo/` | **STM32 HAL 工程**（MDK / CubeMX）—— 机械臂控制代码主体，内部构成见下一小节 | ★★★ 唯一与"机械臂控制代码"直接对应 |
| `姿态解算演示程序.c` | **4 自由度**解析法逆解演示程序（带 `main()`，PC 端运行）—— ⚠ 注意它与仓库标题所说的"六轴机械臂"**不是同一套自由度**（演示程序解的是 4 个角，嵌入式工程控制的是 6 个关节），两者只有**方法同源**，不能当成同一模型 | ★★ 逆解思路可借鉴（仅方法） |
| `视觉部分.py` | **OpenMV 颜色追踪**程序（作者自署"入门学习"） | ★ 视觉链路参考 |
| `README.md` / `readme.txt` | 仓库说明（六轴 + OpenMV 分拣；**机械部分 3D 打印、声明不开源**） | 说明性文字 |

已读到的两个文件的要点（便于写「用在哪」）：

- **`姿态解算演示程序.c`** —— 解析法逆运动学，不是嵌入式代码（有 `main()`，在电脑上算）。给定目标点 `(X,Y,Z)` 反解四个姿态角 `j1..j4`：先用 `j1 = atan((Y+P)/X)×57.3`（X==0 时取 90°）；再**把 `j_all = j2+j3+j4` 从 0° 扫到 180°**，逐步算 `L = len − a4·sin(j_all)`、`H = high − a4·cos(j_all) − a1`，用余弦定理求 `j3`、再求 `j2`、最后 `j4 = j_all − j2 − j3`；约束 `j2,j3∈[0,180]`、`j4∈[−90,90]`。**它的关键技巧是"取中间解"**：第一遍数出全部有效解的个数 `n`，第二遍取第 `n/2`（或 `(n+1)/2`）个——即**在所有可行姿态里挑居中的那个**，避免取到贴极限的奇异位形。示例参数：底台高 `a1=12`、三段臂长 `a2=a3=a4=12`、底盘半径 `P=14`。
- **`视觉部分.py`** —— OpenMV 颜色追踪。作者自署"张天鹏 刘胜昔"，创建 2022-06-13、更新 2022-07-14，用途写的是"**OpenMV 入门学习**"（即教学示例性质）。做法：`RGB565` + `QQVGA 160×120`，关闭自动增益与自动白平衡，`lens_corr(strength=1.8)` 做畸变校正，`find_blobs` 找色块；阈值 `blue_threshold=(3,38,-20,42,-47,-16)`、`yellow_threshold=(25,80,64,-24,47,108)`（注释注明这是"改后"的数据，原值为 `(54,78,-3,44,33,127)`）；识别结果经 **UART3 115200** 发给 STM32，帧格式 `ustruct.pack("<bbbbbb", 0x2c,0x12,color,cx,cy,0x5b)`，其中 `color` 为 `ord('B')` 蓝 / `ord('Y')` 黄 / `ord('A')` 无目标，帧头 `0x2c 0x12`、帧尾 `0x5b`。文件里自己写了注意事项：**颜色追踪必须控制环境光线稳定，否则标志物的色彩阈值会漂移**。

> ⚠ 三点提醒：
> ① 该库是**六轴**臂、用 **6 路 MG996R**；而官方物资表里只有 **MG995×2 + SG90×4**。**我们的 V7 用的是 MG996R×3 + MG90S×3，这两种型号都不在物资表内** —— 这是必须单独处理的合规问题（见 §五 第 4、5 行）。
> ② 它是**教学示例**（`视觉部分.py` 自己写明"入门学习"），不是工程级代码；且其嵌入式工程的主循环分拣流程**被整块注释掉**（见下节"开发中快照"一条），引用时要在文档里说清"参考了什么、我们改成了什么"。
> ③ 它的机械部分声明不开源，**V7 三爪机械臂结构必须完全自研**，不可参考其模型/图纸。

#### 项目 1 工程内部构成（Keil 工程 `robotic_arm_demo.uvprojx` 的官方文件清单）

主控 **STM32F103C8**（Cortex-M3，20 KB RAM / 64 KB Flash），宏 `USE_HAL_DRIVER,STM32F103xB`，**裸机 HAL、无 RTOS**。工程里由**作者自写或手改的共 10 个源文件**（`Core/Src/` 下 8 个：`main.c`、`servo.c`、`gpio.c`、`tim.c`、`usart.c`、`stm32f1xx_it.c`、`stm32f1xx_hal_msp.c`、`openmv.c`；`Core/Inc/` 下 2 个：`servo.h`、`config.h`），其余全是 CubeMX/HAL/CMSIS 自动生成。另有 `Core/Inc/math.h`、`stdio.h` 两个**作者拷进工程的标准库头文件**（各约 50 KB，无研究价值）：

| 文件 | 作用 | 关键内容 |
|---|---|---|
| `Core/Src/servo.c`（606 行） | **机械臂核心** | `pwm_start()` / `translate_angle_to_pulse()` / `pwm_out()` / `servo_angle_calculate()`（逆解）/ `servo_control()`（斜坡）/ `servo_reset()` / `servo_catch()` / `servo_lift*()` / `blue_task()` / `yellow_task()` |
| `Core/Inc/config.h`、`servo.h` | 全局量与接口 | `config.h` 里**直接定义**（不是 `extern`）6 组关节角 / 脉宽变量 |
| `Core/Src/openmv.c`、`openmv.h` | 视觉串口 | 帧解析状态机 + 像素→厘米换算 |
| `Core/Src/main.c` | 主流程 | 外设初始化、USART3 中断接收、主循环 |
| `Core/Src/tim.c` | 舵机 PWM | TIM2 + TIM3 共 8 通道 |
| `Core/Src/usart.c` | 串口 | USART1（`printf` 重定向）/ USART3（OpenMV） |

**已读源码后的取舍清单（这些正是"用在哪"要写的东西）**：

- **逆解 `servo_angle_calculate(x, y, z)`** —— 与 PC 版演示程序同源，但**做了修正**：`j1 = 90 − atan(target_x / (target_y + bottom_r)) × 57.3`（PC 版写的是 `atan((Y+P)/X)`），并把 `target_y` 夹到 `[3, 18]`。臂参数**硬编码在函数体内**：`bottom_r = 14`、`len_1 = 12`、`len_2 = len_3 = len_4 = 12`。**两遍扫描（第一遍数出 `n` 个合法解、第二遍取第 `n/2` 或 `(n+1)/2` 个）与演示程序完全一致** → 说明"取中间解"是他**真正采用**的做法，不只是演示。✅ 我们沿用该思路，但把参数外置为可配置。
- **PWM 与脉宽（可直接引用的定量结论）** —— `tim.c` 里 TIM2/TIM3 都是 `Prescaler = 71`、`Period = 19999` → 计数频率 **1 MHz（1 count = 1 µs）**、周期 20 ms、即 **50 Hz**。因此 `translate_angle_to_pulse()` 中的 `(20000/20)` 系数就是"每毫秒 1000 个计数"，**算出的 `pulse_N` 直接就是以 µs 为单位的脉宽**。⚠ 该函数上方的块注释写的是 "PSC = 72-1，ARR = 200-1"，**与代码不符，是没更新的旧注释**（我们写文档时不要照抄这句）。
  - 引脚：TIM2 = PA0/PA1/PA2/PA3（CH1–4 全配），TIM3 = PA6/PA7/PB0/PB1（CH1–4 全配）→ **共 8 路 PWM，`pwm_start()` 只启动 6 路**（TIM3 四路 = 关节 1–4，TIM2 CH2/CH4 = 关节 5–6），**TIM2 的 CH1/CH3 是空闲备用**。用两个定时器的原因是**单定时器只有 4 个通道**，与频率无关 —— 这与我们"舵机与电机必须分定时器"的理由（频率冲突）是两回事，别混。
  - **每个关节的换算都是手工标定的，没有统一模型**：`angle_1 → (angle_1+70)/90`、`angle_2 → (angle_2+90)/90`、`angle_3 → angle_3/90`、`angle_4 → ((−angle_4+90)/270×180)/90`、`angle_5 → ((angle_5/90×65)+90)/90`、`angle_6 → angle_6/90`。即**每个关节各有一个零点偏置和一个非对称增益** → 说明实际装配的零位与理论对不上，只能一个个量。**这是最值得记下的一条工程经验。**
- **`servo_control()` 的斜坡** —— 逐关节**串行**：算 `fabs(目标 − 当前)`，`for(; 误差 >= 3; 误差--)` 每次 `pwm_out(...)` 后 `HAL_Delay(20)`，即 **1 个角度单位 / 20 ms 的线性爬升**，到位后写精确值，最后 `HAL_Delay(1000)`。**全程阻塞主循环**（没有 RTOS）。关节顺序是 2→3→4→6→5。
  - ⚠ **关节 1（底座旋转）的斜坡被作者注释掉了**，原话是："**抓取部分舵机1不适用，因过多段抓取会导致机械臂无力**" —— 一条真实踩坑记录：分段爬升会削掉舵机的持续力矩。我们改成非阻塞调度时要专门验证这一条。
- **按颜色分两仓** —— `blue_task()` / `yellow_task()` 的唯一差别是**末端腕关节（关节 6）的目标角：蓝 = 160°、黄 = 20°**；其余角度完全相同（`−65, 30, 0, 30, 45`）。即"识别不同物块分放"是靠**一个腕关节的两位切换**实现的，非常省 —— 这个做法值得借鉴。
- **`openmv.c` 帧解析** —— 状态机认帧头 `0x2C` → `0x12`，收满 6 字节（或以 `0xFF` 结束）后从 `rx_buffer_1[n−4]`、`[n−3]`、`[n−2]` 取出**颜色 / x / y**，再等帧尾 `0x5B`；任何异常都清零重来。`coordinate_transformation()` 把像素换成厘米：`ratio_x = 51.1/160`、`ratio_y = 38.2/120`（视场 51.1 cm × 38.2 cm 对应 160×120 像素），且 **y 的零点取 107 而不是 60** —— 相机光心不在图像正中，是实测标定出来的。
- **串口分配** —— USART1（PA9/PA10，115200）做 `printf` 重定向（`fputc` → `HAL_UART_Transmit(&huart1, ...)`），用于调试；USART3（PB10/PB11，115200，且 `HAL_NVIC_SetPriority(USART3_IRQn, 0, 0)` 设为最高优先级）接 OpenMV，**逐字节中断接收**（`HAL_UART_Receive_IT`）。
- ⚠ **重要观察：这份代码是"开发中"的快照，不是跑通的生产版本。** `main.c` 主循环里，整条分拣流程（`coordinate_transformation` → `blue_task()` / `yellow_task()` → `servo_reset()`）**被 `/*YJT ... */` 整块注释掉了**，`servo_reset_begin()` 也注释掉了；循环里实际只剩 `__HAL_TIM_SetCompare(&htim2, TIM_CHANNEL_4, 16000)`（16 ms 脉宽）这类台架调试语句，以及一段算完就不用的 `pulse_1` 死代码。**引用它时要如实写成"参考其算法与结构"，不能说成"采用其成熟控制程序"。**
- 另有若干代码质量问题，我们自己写时要避免：`config.h` 在**头文件里定义全局变量**（无 `extern`，靠只被包含一次才不报错）；`if (pulse_1 != NULL)` 拿 `double` 和 `NULL` 比；`config.h` 里 `theta_4` **重复声明了两次**；`servo.h` 声明了 `servo_transfer()` 但实现叫 `servo_transfer_blue/yellow()`。
