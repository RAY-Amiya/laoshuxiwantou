### 2. 初版构思

用 FreeRTOS 做多任务，按**实时性要求**分优先级，而不是按功能模块分：

| 任务                | 优先级 | 周期        | 职责                   |
| ----------------- | --- | --------- | -------------------- |
| `motor_ctrl`  | 最高  | 10 ms | 读目标速度 → 麦轮解算 → PWM 输出 → 读电流 |
| `ps2_poll`    | 高   | 20 ms | 轮询 PS2 手柄，写共享目标速度    |
| `servo_ctrl`  | 中   | 20 ms | 6 路舵机角度插值与限速（肩 / 肘 / 腕 + G1–G3） |
| `health`      | 最低  | 100 ms | 电流/温度监控、失联检测、喂看门狗 |

共享数据用临界区或消息队列保护。

风险预判：

- 舵机 PWM 和电机 PWM 如果共用一个定时器，改舵机就会扰动电机频率。
- PS2 手柄是**位时序敏感器件**（4 线 GPIO 位模拟，不走 SPI 外设），在中断里做长阻塞会拖垮其他任务。
- 手册要求"一方全部机器人 1 分钟内没有任何运动或机构活动即结束对局"——**软件死锁会直接导致本局结束并判负**，必须有看门狗。

### 3. 技术选型对比

**选型 1：调度方式**

| 候选方案              | 优点                       | 缺点                  | 结论       |
| ----------------- | ------------------------ | ------------------- | -------- |
| 裸机前后台（while + 中断） | 资源占用最小、延迟可预测             | 任务一多就难维护；视觉串口一阻塞就失控 | ❌        |
| **FreeRTOS 多任务**  | 优先级明确；阻塞不影响高优先级任务；官方培训覆盖 | 需要栈空间规划；共享数据要加保护    | ✅ **选定** |
| 时间片轮询             | 简单                       | 实时性无保证              | ❌        |

**选型 2：PWM 资源分配**

| 候选方案                          | 优点          | 缺点                  | 结论       |
| ----------------------------- | ----------- | ------------------- | -------- |
| 电机与舵机共用 1 个定时器                | 省定时器        | 改舵机频率会扰动电机；四路电机占满通道 | ❌        |
| **电机用 TIMx 4 通道 + 舵机用另一个定时器** | 互不干扰；可各自设频率 | 需要确认芯片定时器数量够        | ✅ **选定** |
| 软件 PWM                        | 不占硬件        | 抖动大，舵机会抖            | ❌        |

**为什么这么选**：STM32F103C8T6 有 4 个通用定时器，其中 TIM1 是高级定时器。把 **4 路电机放在 TIM4 的 4 个通道**上，保证 4 个轮子的 PWM 频率与相位完全一致（否则麦轮解算出来的速度比例会被 PWM 抖动破坏）；**6 路舵机分到 TIM2（3 路）与 TIM3（3 路，部分重映射）**，两边都设成 50 Hz。定时器分工、引脚冲突与 JTAG 关闭这些细节，完整表在 [05-机械臂电控.md](05-机械臂电控.md)。**本工程不接视觉**（V7/V8 已取消 OpenMV），因此没有视觉串口这一路。

### 5. 遇到的问题与解决

#### 问题 1：舵机动作时底盘会"抽搐"

- **现象**：舵机一动，四个轮子的转速就抖一下，严重时车体猛冲；示波器上能同时看到电机 PWM 的占空比跳变。
- **定位过程**：① 单独动舵机、不动电机（仍抽搐）→ 排除电机代码问题；② 用示波器同时看舵机 PWM 与电机 PWM（舵机动作瞬间电机占空比跳变）→ 是 PWM 通道互相干扰；③ 查代码发现两个功能共用同一个定时器的预分频/自动重装寄存器。
- **根因**：**舵机与电机共用定时器**——改舵机的 PSC/ARR 会同时改变电机的 PWM 频率与相位，麦轮解算出来的速度比例随之被破坏。
- **对策**：电机**独占 TIM4**（PB6–PB9，20 kHz）；6 路舵机改走 **TIM2（PA0/PA1/PA2）+ TIM3（PB4/PB5/PB0，部分重映射把默认脚 PA6/PA7 让给 DRV8833 方向脚）**，两边都设 PSC=71 / ARR=19999，即 50 Hz、1 count = 1 µs；频率定死后**运行期不再改 PSC/ARR**。
- **验证结果**：`<待实测：6 路舵机同时动作，看四轮转速波动>`。

#### 问题 2：PS2 手柄轮询阻塞导致底盘响应迟滞

- **现象**：手柄轮询期间底盘有 10 ms 级的顿挫，快速打杆时尤其明显。
- **定位过程**：① 把轮询周期从 10 ms 放到 20 ms（顿挫变明显）→ 说明与轮询同步；② 换成中断方式（顿挫消失）→ 确认是轮询占用了 CPU；③ 提高 `motor_ctrl` 优先级后顿挫减轻但没消失。
- **根因**：PS2 一帧 9 字节要在**位级别**拉时序，阻塞式轮询期间高优先级任务拿不到 CPU。
- **对策**：`ps2_poll` 保持高优先级但**允许被 `motor_ctrl` 抢占**；把一帧内的位时序压缩到最短，帧与帧之间主动让出 CPU；`motor_ctrl` 用 10 ms 固定周期 + 硬件 PWM，不依赖轮询间隔。
- **验证结果**：`<待实测：快速打杆时测轮速跟随延迟>`。

#### 问题 3：长时间运行后整机停住，只能复位

- **现象**：连续跑十几分钟后偶发整机停住，舵机与电机都不动，串口也不再输出，只有按复位才恢复。
- **定位过程**：① 复现时用调试器暂停，看到多个任务卡在同一把临界区上；② 检查共享数据结构，发现手柄任务在临界区内又调用了会阻塞的串口打印。
- **根因**：**临界区内调用阻塞函数**——抢占被关掉的这段时间里其他任务全部饿死，一旦打印阻塞就再也出不来。
- **对策**：临界区只保留最少的变量拷贝；所有打印移到临界区外；独立看门狗 **IWDG 500 ms**，由 `health` 任务喂狗，任何任务停转都会触发复位。
- **验证结果**：`<待实测：连续跑 30 min 不掉线>`。

### 2. 初版构思

DRV8833 有 **IS 引脚输出电流镜比例电流**，把它接到 STM32 的 ADC 上就能实时读电流，实现软件过流保护。供电用官方物资表的 Mini 降压模块（5 V）。

风险预判：

- Mini 降压模块的电流能力有限，4 路电机同时启动的浪涌可能把 5 V 拉低，导致 MCU 复位。
- TT 马达堵转电流可达几安培，DRV8833 的额定电流会被超过。
- 手册限制**只有 1 个供电模块**，不能为了电流余量再加一路。

### 3. 技术选型对比

**选型 1：过流保护方式**

### 5. 遇到的问题与解决

#### 问题 1：四路电机同时启动时 MCU 复位

- **现象**：四路电机同时启动的瞬间 MCU 复位，车体短暂失控，串口打印从头开始。
- **定位过程**：① 单路启动（正常）→ 四路同启（复位）；② 示波器抓 5 V 轨（启动瞬间跌到 3.1 V 左右）；③ 把 MCU 单独用电池供电（不再复位）→ 确认是 5 V 轨被拉低；④ 逐步加大入口电容，找到能稳定的最小容量。
- **根因**：Mini 降压模块的瞬态输出能力不足，四路启动浪涌叠加把 5 V 轨拉崩，MCU 掉到欠压复位阈值以下。
- **对策**：软件上让四路电机**错开 20 ms** 启动，避免浪涌叠加；硬件上加大入口电容（220–470 µF）；MCU 供电单独加 LC 滤波；舵机与电机统一走一套错峰调度器。
- **验证结果**：`<待实测：四路同启 + 6 路舵机同时动作，抓 5 V 轨最低点>`。

#### 问题 2：堵转几次后该路驱动失效

- **现象**：撞上台阶后电机堵转，DRV8833 附近明显发烫；反复几次后该路彻底没有输出。
- **定位过程**：① 按住轮子强制堵转 5 s → 驱动板发烫；② 读 IS 电流（远超额定）；③ 不干预连续堵转 3 次 → 该路无输出，需断电才恢复。
- **根因**：TT 马达堵转电流可达数安培，远超 DRV8833 的持续能力；片子内部的过温保护虽然会动作，但**不防长时间堵转**，热量已经积在芯片里。
- **对策**：IS 采样 + **100 ms 内把占空比降到 0** 并置堵转标志；堵转后自动回退 0.5 s 再试，连续 3 次锁定，须松杆才复位。
- **验证结果**：`<待实测：堵转 5 s 后测驱动板温度与输出能否恢复>`。

### 2. 初版构思

PS2 手柄通过 **4 线 GPIO 位模拟**与接收器通信（CS / CLK / DAT / CMD 各一根，不占用 SPI1 外设）。按官方培训的「SPI 以及 PS2 手柄的使用」实现按键读取与摇杆映射，并把手柄的 `START/SELECT` 用作使能开关。

风险预判：

- 手柄是**无线**的，比赛现场 2.4G 环境拥挤，可能丢包。
- 手册要求"收发源唯一"，所以车上不能再开蓝牙/WiFi 做调试——调试要用有线串口。
- 手柄需**提前对频锁定**（官方款式），两车若共用一个频段可能互相抢占，必须分别对频。
- **失联保护**：如果手柄掉线而软件还在按上一帧指令跑，机器人会冲出去——这在有围挡（500 mm 高）的场地里可能撞坏对手，触发"恶意冲撞"判罚（立即断电 20 s，情节恶劣当局判负）。

{
    static const uint8_t ps2_cmd[9] =
    {
        0x01, 0x42, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00
    };

    PS2_TransferFrame(ps2_cmd, ps2_data);

    /* 第 2 字节是模式字节：0x41=数字模式，0x73/0x79=模拟模式 */
    if ((ps2_data[1] == 0x41) || (ps2_data[1] == 0x73) || (ps2_data[1] == 0x79))

        ps2_online = 1;
    }

    ps2_analog = (uint8_t)((ps2_data[1] == 0x73 || ps2_data[1] == 0x79) ? 1 : 0);

        ps2.select = ps2.start = 0;
        ps2.l1 = ps2.l2 = ps2.r1 = ps2.r2 = 0;
        ps2.l3 = ps2.r3 = 0;
        ps2.triangle = ps2.circle = ps2.cross = ps2.square = 0;
        ps2.lx = ps2.ly = ps2.rx = ps2.ry = 0;
        ps2_analog = 0;             /* 断了就绝不允许用摇杆值驱动电机 */
        return;
    }

    /* --- 方向键 + 功能键：ps2_data[3] --- */
    ps2.select  = ((ps2_data[3] & PS2_MASK_SELECT) == 0) ? 1 : 0;
    ps2.l3      = ((ps2_data[3] & PS2_MASK_L3)     == 0) ? 1 : 0;
    ps2.r3      = ((ps2_data[3] & PS2_MASK_R3)     == 0) ? 1 : 0;
    ps2.start   = ((ps2_data[3] & PS2_MASK_START)  == 0) ? 1 : 0;
    ps2.up      = ((ps2_data[3] & PS2_MASK_UP)     == 0) ? 1 : 0;
    ps2.right   = ((ps2_data[3] & PS2_MASK_RIGHT)  == 0) ? 1 : 0;
    ps2.down    = ((ps2_data[3] & PS2_MASK_DOWN)   == 0) ? 1 : 0;
    ps2.left    = ((ps2_data[3] & PS2_MASK_LEFT)   == 0) ? 1 : 0;

    /* --- 肩键 + 四色键：ps2_data[4] --- */
    ps2.l2       = ((ps2_data[4] & PS2_MASK_L2)       == 0) ? 1 : 0;
    ps2.r2       = ((ps2_data[4] & PS2_MASK_R2)       == 0) ? 1 : 0;
    ps2.l1       = ((ps2_data[4] & PS2_MASK_L1)       == 0) ? 1 : 0;
    ps2.r1       = ((ps2_data[4] & PS2_MASK_R1)       == 0) ? 1 : 0;
    ps2.triangle = ((ps2_data[4] & PS2_MASK_TRIANGLE) == 0) ? 1 : 0;
    ps2.circle   = ((ps2_data[4] & PS2_MASK_CIRCLE)   == 0) ? 1 : 0;
    ps2.cross    = ((ps2_data[4] & PS2_MASK_CROSS)    == 0) ? 1 : 0;
    ps2.square   = ((ps2_data[4] & PS2_MASK_SQUARE)   == 0) ? 1 : 0;

    /* --- 摇杆模拟量：仅模拟模式下是 0~255（中位约 128） --- */
    ps2.rx = ps2_data[5];
    ps2.ry = ps2_data[6];
    ps2.lx = ps2_data[7];
    ps2.ly = ps2_data[8];
}

### 5. 遇到的问题与解决

#### 问题 1：两车同时开机后手柄互相干扰

- **现象**：两车同时开机后，一台车的操作会让另一台也跟着动。
- **定位过程**：① 单车上电（正常）→ 第二台上电后第一台开始乱动；② 交换两车的手柄（问题跟着手柄走）→ 说明是同频；③ 按官方说明重新对频到不同通道。
- **根因**：两只手柄出厂在同一频段/通道，接收器不认发送方，谁发的都执行。
- **对策**：按官方说明把两车手柄分别对频到不同通道，并在开机自检里显示当前通道；比赛现场两车**不同时开机**，先开一台再开另一台。
- **验证结果**：`<待实测：两车同时开机互相打杆 10 次>`。

#### 问题 2：走远或背对车体时手柄突然失灵，车仍在跑

- **现象**：离车 10 m 以外或背对车体时手柄突然失灵，车继续按上一帧指令往前冲。
- **定位过程**：① 逐距离测试（2 / 5 / 10 m）记录丢包；② 观察失联后车体行为（仍在跑）→ 说明没有超时处理。
- **根因**：2.4G 在拥挤环境会丢包，而软件此时仍把上一帧的按键与摇杆值当成有效指令。
- **对策**：超时 **100 ms** 无新帧即清零所有按键与摇杆；`ps2_online` 为 0 时**绝不允许**用摇杆值驱动电机（见上方 `PS2_Parse()` 的失联分支）。
- **验证结果**：`<待实测：拔掉接收器计时到停转>`。
